# 系统负载高分析

## 原理

### 系统负载是什么？

在Linux上，**uptime与top**命令，都可以看到系统的平均负载(load average)，如下：

```sh
[root@server01 ~]# uptime
 18:54:12 up 653 days, 18:55,  2 users,  load average: 0.20, 0.13, 0.14
```

关注load average后的3个值，分别代表**1分钟、5分钟、15分钟**的系统平均负载，如果1分钟值>5分钟值>15分钟值，则代表近15分钟内系统压力越来越大，反之亦然。

在传统unix系统上（如BSD），系统负载由**正在运行**及**可运行**这2个状态的线程数量组成。 它能很好的反映**CPU的饱和情况**，比如4核的CPU，如果负载一直高于4，那说明CPU资源饱和了。

<img src="7.%E7%B3%BB%E7%BB%9F%E8%B4%9F%E8%BD%BD%E9%AB%98%E5%88%86%E6%9E%90.assets/image-20260312185507283.png" alt="image-20260312185507283" style="zoom:50%;" />

在Linux里面，线程有如下常见状态：

- **R**：线程正在 CPU 上跑，或者在就绪队列里排队。
- **S (Interruptible Sleep)**：被阻塞进入睡眠状态，可以接收信号被唤醒
- **D (Uninterruptible Sleep)**：不可中断睡眠状态， **不响应任何信号**， 一般是在等待磁盘io完成
- **T (Stopped)**：线程被挂起。
- **Z (Zombie)**：线程运行完了，但所属的进程还没来得及回收它（通常进程退出时会统一回收）。

| **状态符号** | **状态名**   | **是否占用 CPU** | **是否可被信号杀死**        |
| ------------ | ------------ | ---------------- | --------------------------- |
| **R**        | 运行/就绪    | **是/就绪**      | 是                          |
| **S**        | 可中断睡眠   | 否               | 是                          |
| **D**        | 不可中断睡眠 | 否               | **否** (需等 IO 完成)       |
| **T**        | 停止         | 否               | 是                          |
| **Z**        | 僵尸         | 否               | 已经是死的 (需杀掉其父进程) |

而Linux扩大了负载的定义，如下：

Linux负载由**正在运行**、**可运行**及**D状态**这3个部分的线程数量组成。

<img src="7.%E7%B3%BB%E7%BB%9F%E8%B4%9F%E8%BD%BD%E9%AB%98%E5%88%86%E6%9E%90.assets/image-20260312185905428.png" alt="image-20260312185905428" style="zoom:50%;" />

简单来说，平均负载是指单位时间内，系统处于**可运行状态**和**不可中断状态**的平均进程数，也就是**平均活跃进程数**，它和 CPU 使用率并没有直接关系。这里我先解释下**可运行状态**和**不可中断状态**这两个概念：

- 所谓可运行状态的进程，是指正在使用 CPU 或者正在等待 CPU 的进程，也就是我们常用 ps 命令看到的，处于 R 状态（Running 或 Runnable）的进程。
- 不可中断状态的进程则是正处于内核态关键流程中的进程，并且这些流程是不可打断的，比如最常见的是等待硬件设备的 I/O 响应，也就是我们在 ps 命令中看到的 D 状态（Uninterruptible Sleep，也称为 Disk Sleep）的进程。

比如，当一个进程向磁盘读写数据时，为了保证数据的一致性，在得到磁盘回复前，它是不能被其他进程或者中断打断的，这个时候的进程就处于不可中断状态。如果此时的进程被打断了，就容易出现磁盘数据与进程数据不一致的问题。

所以，**不可中断状态实际上是系统对进程和硬件设备的一种保护机制**。

既然平均的是活跃进程数，那么最理想的，就是每个 CPU 上都刚好运行着一个进程，这样每个 CPU 都得到了充分利用。比如当平均负载为 2 时，意味着什么呢？

- 在只有 2 个 CPU 的系统上，意味着所有的 CPU 都刚好被完全占用。
- 在 4 个 CPU 的系统上，意味着 CPU 有 50% 的空闲。
- 而在只有 1 个 CPU 的系统中，则意味着有一半的进程竞争不到 CPU。

### Linux线程状态

因为Linux认为，虽然D状态的线程并不消耗CPU资源，但是它会消耗磁盘等资源，因此它也应该被用来计算系统负载，想想也合理，毕竟系统负载是用来描述整个系统的繁忙程度的，而不仅仅是CPU的。

R与D状态的线程会影响系统负载，因此，当系统负载较高时，可以通过`ps -eLo pid,tid,s,comm | awk '$3 ~ /R|D/'`命令了解是哪些线程导致的：

<img src="7.%E7%B3%BB%E7%BB%9F%E8%B4%9F%E8%BD%BD%E9%AB%98%E5%88%86%E6%9E%90.assets/image-20260312185932672.png" alt="image-20260312185932672" style="zoom:50%;" />

**第一部分：`ps -eLo pid,tid,s,comm`**

- **`-e`**: 列出全系统所有进程。
- **`-L`**: 显示线程（如果你记得我们之前聊的，这会让每个线程占一行）。
- **`-o pid,tid,s,comm`**: 自定义输出列：
  - **pid**: 进程 ID。
  - **tid**: 线程 ID（在 `ps` 里 `tid` 和 `lwp` 几乎是等价的）。
  - **s**: 进程状态（简略版（单字符），如果是stat则是输出完整的状态）。
  - **comm**: 命令简称。

**第二部分：`awk '$3 ~ /R|D/'`**

- 这是对前面的结果进行**过滤**。
- **`$3`**: 指的是第三列，也就是状态（`s`）那一列。
- **`~ /R|D/`**: 匹配状态为 **R** (Running，正在运行) 或 **D** (Uninterruptible Sleep，不可中断睡眠，通常是在等磁盘 IO)。

通过ps命令可以看到线程状态，还有一个**wchan**字段，它显示的是线程当前被阻塞在什么内核函数上，这能看出一些蛛丝马迹。

可以发现，D状态线程阻塞在`kernel_clone()`内核函数上。

也可以借助**`/proc/$pid/task/$tid/stack`**伪文件查看，它记录着线程阻塞时的内核栈，如下：

可发现D状态线程由vfork系统调用发起，阻塞在kernel_clone内核函数上，如果要看所有D线程的内核栈，可通过shell命令聚合后查看，如下：

<img src="7.%E7%B3%BB%E7%BB%9F%E8%B4%9F%E8%BD%BD%E9%AB%98%E5%88%86%E6%9E%90.assets/image-20260312234456874.png" alt="image-20260312234456874" style="zoom:50%;" />

bcc的**offcputime**命令，可通过**--state 2**过滤出只包含D状态线程的offcpu栈。（只看那些处于 **D 状态** 的线程，到底是因为什么原因离开 CPU 的）

`offcputime` 是 **BCC (BPF Compiler Collection)** 工具集中的一个神器。它利用 eBPF 技术，在内核调度器切换上下文时进行插桩。

- **它的功能：** 记录进程离开 CPU 到重新回到 CPU 之间的那段时间，并捕获此时的**内核栈（Stack Trace）**。
- **它的产出：** 它会输出一个汇总图（通常是折叠的栈格式），告诉你是哪段代码路径导致了最长的等待时间。

**--state 2**是用来**过滤进程状态**的。在 Linux 内核源码中，进程状态是用位掩码（bitmask）定义的。

在 `offcputime` 中，`--state` 对应的是内核中 `task_struct->state` 的值：

| **数值** | **内核常量**           | **对应状态** | **含义**                                        |
| -------- | ---------------------- | ------------ | ----------------------------------------------- |
| **0**    | `TASK_RUNNING`         | **R**        | 实际上 Off-CPU 很少捕获这个，除非是被抢占。     |
| **1**    | `TASK_INTERRUPTIBLE`   | **S**        | 可中断睡眠（如等待常规网络包）。                |
| **2**    | `TASK_UNINTERRUPTIBLE` | **D**        | **不可中断睡眠（如等待磁盘 IO、vfork 资源）。** |

在D状态线程的offcpu栈中，也可发现是由vfork系统调用导致的负载升高。

## 总结

1. Linux扩充了系统负载定义，它反映的是**一段时间内处于运行中、可运行(R)及不可中断(D)线程的平均数量**。
2. 可通过ps查看线程的**wchan**字段，了解D状态线程阻塞在什么内核函数上。
3. **`/proc/$pid/task/$tid/stack`**反映线程当前的内核栈，它可用来查看D状态线程当前在做什么。
4. bcc的**offcputime**命令，可通过**--state 2**过滤出只包含D状态线程的offcpu栈。
